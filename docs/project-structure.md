# Project structure

`plombir new my-site` generates exactly this tree (verified against
`src/scaffold/site.cr`; nothing more, nothing less):

```text
my-site/
├── content/
│   ├── index.md              # → /
│   ├── posts/hello-world.md  # → /posts/hello-world/
│   └── pages/about.md        # → /pages/about/
├── layouts/
│   ├── default.html
│   └── post.html
├── components/               # .gitkeep (add PostCard.html, …)
├── assets/images/            # .gitkeep (fingerprinted into dist/assets/)
├── public/
│   ├── assets/style.css      # copied as-is (wins over generated files)
│   └── .gitkeep
├── plombir.yml               # optional config (defaults cover everything)
├── .gitignore                # ignores dist/ and .plombir/
└── dist/                     # generated by build, gitignored
```

## Conventions

- **Routing:** `content/<path>.md` → `/<path>/` (pretty URLs;
  `content/index.md` → `/`). A `permalink: /custom/url/`
  frontmatter value overrides the convention. See `content.md`.
- **`assets/` vs `public/`:** files under `assets/` are fingerprinted
  (`style.A1B2C3.css`) and referenced via `| asset_url` or absolute
  `/assets/…` paths; files under `public/` are copied verbatim and
  win on collision. See `assets.md`.
- **Layouts:** frontmatter `layout:` picks `layouts/<name>.html`
  (default `default`); `{{ content }}` receives the page HTML. See
  `templates.md` and `layouts.md`.
- **Config:** `plombir.yml` is optional — a site without it builds
  with defaults. See `config.md`.
- **Generated:** `dist/` (the deployable site) and `.plombir/`
  (build cache) are the only generated paths; `plombir clean`
  removes both.
